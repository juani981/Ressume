# Architectural & CSS Divergence Survey: Live Editor (`#area-cv`) vs Clean Print Output

**Investigator**: Explorer 1 (Project Orchestrator 10)  
**Target Repository**: Ressume  
**Scope**: `src/utils/staticHtmlPdfEngine.js`, `src/App.jsx`, `src/index.css`, `src/styles/print.css`, and related CV components.  
**Standard**: Strict 0px Visual & Geometric Parity (Editor vs Clean Print / PDF).

---

## 1. Executive Summary

A deep, line-by-line static analysis and DOM behavior audit reveals that the visual discrepancies between the interactive editor (`#area-cv`) and the print output generated by `generateCleanPrintHTML` / `executeCleanPrint` stem from **eight systemic sources of divergence**.

The divergences are not mere rounding errors. They result from:
1. **Destructive regex replacements** in `staticHtmlPdfEngine.js` that strip core typography, spacing, and inheritance rules from the injected base CSS.
2. **Artificial horizontal padding** (`padding: 0 0.25rem`) injected on print components to compensate for the damaged CSS, which does not exist in editor components.
3. **Container structural mismatches**: Missing class names (`bd-grid`), redundant nested wrapper elements in 1-column mode, and hardcoded `width: 100% !important` overrides in print stylesheets that defeat the 794px A4 container contract.
4. **Desktop media query leakage** (`@media screen and (min-width: 968px)`) in `src/index.css`: Critical layout grids and gap rules (contacts, languages, interests, headers) only exist inside this desktop query, which is ignored in print media and within the 794px print iframe.
5. **Print lifecycle flaws**: Artificial `margin-top` injections on forced page breaks pushing page 2 content downwards, and fallback auto-scaling downscaling document zoom below 1.0.
6. **Concealment mechanism distortion**: Using `visibility: hidden` instead of `display: none` for in-flow interactive artifacts (`.column-add-section`, `.bullet-add-row`, `.contact-del-btn`, `.add-contact-btn`), leaving phantom whitespace and bloated pill dimensions in native print.
7. **Component template divergences**: Divergent markup between `EditView` and `PrintView` in Bullet Points, InlineEdit, Hyperlinks, and Spacers.
8. **Color and fallback variable mismatches**: Mismatched default background hex codes (`#f3f4f6` vs `#fafafa` vs `#F8FAFC`) and inconsistent padding fallbacks.

Eliminating these eight root causes will establish 100% 0px visual parity without altering the underlying data model or introducing regressions.

## 2. In-Depth Technical Catalog of Divergences

### Divergence 1: Destructive Regex Stripping in `staticHtmlPdfEngine.js`

- **Affected File**: `src/utils/staticHtmlPdfEngine.js`
- **Lines**: 448–464
- **Code**:
  ```javascript
  const editorArtifactsPattern = /(?:drag-handle|round-btn-del|round-btn-add|suggestion-tooltip|obsidian-callout|column-resizer|l-navbar|inline-input|editable-section-container|editable-item-container|section-del-btn|item-del-btn|section-add-container|action-menu|no-print|add-contact-btn|contact-del-btn|spacer-resize-handle|spacer-controls-bar)/gi;
  activeBaseStyles = activeBaseStyles
    .replace(/[^{}]*?(?:drag-handle|round-btn-del|round-btn-add|suggestion-tooltip|obsidian-callout|column-resizer|l-navbar|inline-input|editable-section-container|editable-item-container|section-del-btn|item-del-btn|section-add-container|action-menu|no-print|add-contact-btn|contact-del-btn|spacer-resize-handle|spacer-controls-bar)[^{]*?\{[^}]*?\}/gi, '')
    .replace(editorArtifactsPattern, 'editor-control-stripped');
  ```
- **Mechanism of Failure**:
  The regex matches any text from the prior `{` or `}` up to the closing `}` if ANY selector in the rule contains one of the listed artifact classes.
  In `src/index.css`, multiple selectors are grouped by commas for shared rules:
  1. `src/index.css:169-174`:
     ```css
     .section,
     .cv-section,
     .editable-section-container {
       margin-bottom: var(--section-gap, 20px) !important;
       position: relative;
     }
     ```
     Because `editable-section-container` is present, the regex **deletes the entire rule**, stripping `margin-bottom: var(--section-gap, 20px) !important;` from `.cv-section`!
  2. `src/index.css:176-180`:
     ```css
     .cv-section:last-of-type,
     .editable-section-container:last-of-type,
     .section:last-of-type {
       margin-bottom: 0 !important;
     }
     ```
     **Entire rule deleted.**
  3. `src/index.css:1479-1489`:
     ```css
     .resume__left,
     .resume__right,
     .resume__single-column,
     .cv-section,
     .cv-block,
     .editable-section-container,
     .editable-item-container,
     .profile__description,
     .experience__description {
       color: var(--text-color);
     }
     ```
     **Entire rule deleted.**
  4. `src/index.css:1491-1524`:
     Inheritance rule matching all child text elements (`.cv-section p`, `.cv-block span`, etc.) is deleted because `.editable-item-container` is included in the selector group.
  5. `src/index.css:1703-1754`:
     The `@media print` suppression rules themselves are stripped because they contain `action-menu`, `drag-handle`, etc.
- **Architectural Fallacy**:
  Stripping CSS selectors is redundant because `generateCleanPrintHTML` already generates clean semantic markup without any of these elements. A CSS selector that does not exist in the DOM has zero impact on rendering. Attempting to strip it via regex causes catastrophic collateral damage to real layout rules.

### Divergence 4: Desktop Media Query Leakage (`@media screen and (min-width: 968px)`)

- **Affected File**: `src/index.css`
- **Lines**: 583–655
- **Mechanism of Failure**:
  The responsive layout rules that format the CV on desktop viewports are wrapped inside `@media screen and (min-width: 968px)`.
  When printing or rendering inside the 794px iframe:
  1. The print media type is `print`, so `@media screen` is ignored.
  2. The iframe viewport width is `794px`, which is strictly `< 968px`.
- **Divergent Rules Lost in Print**:
  | Selector | Rule in Desktop Editor (`> 968px`) | Base Rule Applied in Print / 794px Iframe | Discrepancy Impact |
  |---|---|---|---|
  | `.home__container` | `gap: 1.5rem` | `gap: 3rem` (`index.css:321`) | 24px excess vertical gap in header |
  | `.social__container` | `grid-template-columns: repeat(3, max-content)` | `grid-template-columns: max-content; gap: 1rem;` (`index.css:385`) | 3-column contact list collapsed into 1 vertical column |
  | `.languages__content` | `grid-template-columns: repeat(2, max-content); column-gap: 3.5rem;` | `grid-template-columns: repeat(2, 1fr); gap: 0;` (`index.css:492`) | Completely altered column widths and missing gap |
  | `.interests__container` | `grid-template-columns: repeat(4, max-content); column-gap: 3.5rem;` | `grid-template-columns: repeat(3, 1fr);` (`index.css:540`) | 4-column layout collapsed to 3-column |

  | `.section-title` | `text-align: initial` | `text-align: center` (`index.css:209`) | Centers titles if print.css doesn't override |

### Divergence 5: Print Lifecycle & Page-Break Margin Injections

- **Affected File**: `src/utils/staticHtmlPdfEngine.js`
- **Lines**: 804–825, 878–881
- **A. Artificial `margin-top` on Page Breaks**:
  In `executeCleanPrint`:
  ```javascript
  targetEl.style.setProperty('break-before', 'page', 'important');
  targetEl.style.setProperty('page-break-before', 'always', 'important');
  targetEl.classList.add('force-page-break-before');
  targetEl.setAttribute('data-page-break-forced', 'true');
  targetEl.setAttribute('data-page-break-fold', String(b.fold || b.pageNum || 1));

  const pageNum = parseInt(b.fold || b.pageNum, 10) || 1;
  const foldY = pageNum * pageHeightPx;
  let top = ...;
  const pushDistance = Math.max(0, foldY - top);
  if (pushDistance > 0) {
    targetEl.style.setProperty('margin-top', `${pushDistance + 10}px`, 'important');
  }
  ```
  - In the live editor, `pushDistance` was added to push the element visually below the on-screen 20px fold badge within the continuous scroll.
  - In print, setting `break-before: page` already places the element at the top of the next page.
  - Adding `margin-top: ${pushDistance + 10}px !important` pushes the element downwards from the top margin of page 2, leaving an enormous blank space!
  - Furthermore, `generateCleanPrintHTML` sets `break-before: page` via CSS (lines 411–416) WITHOUT `margin-top`, creating an internal divergence between `generateCleanPrintHTML` and `executeCleanPrint`!

- **B. Fallback Auto-Scale Downscaling**:
  Lines 878–881:
  ```javascript
  const scale = calculatePrintScale(rawHeight, Math.max(2, totalPages));
  if (scale < 1.0 && doc.body?.style) {
    doc.body.style.zoom = scale;
  }
  ```
  If `snapshot` is not provided (or in headless test environments), it computes a scale factor down to 0.75 and sets `body.style.zoom = scale`, violating the requirement:
  *"Document zoom is strictly guaranteed to be 1.0 during print and snapshot generation."*

## 4. Concrete Recommendations for 100% 0px Visual Parity

### Step 1: Fix `staticHtmlPdfEngine.js` Stylesheet & Class Handling
1. **Remove CSS Regex Stripping**:
   Eliminate lines 448–464 in `src/utils/staticHtmlPdfEngine.js`. Do not run regex deletions against `baseStyles` or `printStyles`. The static HTML generated by React does not contain interactive elements anyway.
2. **Add `bd-grid` in 2-Column Mode**:
   In `generateCleanPrintHTML`, change line 387:
   ```javascript
   const areaCvClasses = is2Col 
     ? `resume bd-grid ${isAtsMode ? 'resume--ats-mode' : ''}`.trim()
     : `resume resume__single-column ${isAtsMode ? 'resume--ats-mode' : ''}`.trim();
   ```
3. **Synchronize Default Background & Spacing**:
   Change line 373 to match `App.jsx`:
   ```javascript
   const leftBg = layout.leftBg || '#f3f4f6';
   ```
4. **Remove Artificial Margin Injection on Page Breaks**:
   In `executeCleanPrint`, remove lines 821–824 (`targetEl.style.setProperty('margin-top', ...)`). CSS `break-before: page !important;` already places the item cleanly at the start of the next page.
5. **Guarantee Strictly 1.0 Zoom**:
   In `executeCleanPrint`, set `doc.body.style.zoom = 1.0;` unconditionally. Never invoke `calculatePrintScale` to downscale the document.

### Step 2: Fix Container & Print CSS in `src/styles/print.css` and `src/index.css`
1. **Strict 794px Container Contract**:
   Update `src/styles/print.css` (lines 35–44, 220–227) and `src/index.css` (lines 1797–1805):
   ```css
   #area-cv,
   .resume {
     width: 794px !important;
     max-width: 794px !important;
     min-width: 794px !important;
     margin: 0 auto !important;
     box-sizing: border-box !important;
   }
   ```
2. **Eliminate Double-Padding in 1-Column Mode**:
   Scope `.resume__single-column` padding specifically to `#area-cv.resume__single-column`:
   ```css
   #area-cv.resume__single-column {
     padding: var(--page-padding, 24px) !important;
   }
   ```
   Ensure child `.resume__single-column` inside `#area-cv` does not declare padding.
3. **Extract Document Layout Rules from `@media screen and (min-width: 968px)`**:
   Move document-level rules (`.home__container`, `.social__container`, `.languages__content`, `.interests__container`, `.resume__left, .resume__right`) out of `@media screen and (min-width: 968px)` and into the base stylesheet so they apply identically in screen, print, and the 794px iframe.
4. **Interactive Controls Suppression**:
   In `src/index.css` `@media print`, distinguish between out-of-flow and in-flow elements:
   - Floating buttons, drag handles, tooltips, action bars: `display: none !important;`.
   - `.column-add-section`, `.bullet-add-row`: `display: none !important;`.
   - Ensure `.contact-del-btn` is positioned absolutely within `.contact-item-pill` so its presence never adds 19px of inline flow width.

### Step 3: Remove Component-Level Artificial Padding and Synchronize Markup
1. **BaseSection & BaseItem**:
